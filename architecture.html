REFERENCE: AWS

Why each choice

Decisions justified against published research.

01 · MESSAGE BROKER

Amazon SQS — managed, not self-hosted

Comparative studies of Kafka, Pulsar, Artemis and RocketMQ show broker choice is a throughput-vs-operations trade-off. For job dispatch (consume once, no replay), a managed queue removes broker ops entirely; Kafka returns only if streaming analytics is added later.

02 · WORKERS

Containers, not serverless

Serverless reviews document cold-start latency and per-request limits. Long-running jobs (video transcoding) fit containers better — while queue-driven autoscaling keeps the fleet elastic. This initial design is CPU-only on Fargate; GPU media jobs would need EC2-backed tasks and are out of scope.

03 · SCALING

Scale on backlog, not CPU

Target-tracking on backlog-per-worker: with backlog B, average job time s and wait target T, keep roughly ceil(B × s / T) workers. Research on event-queue autoscaling shows these parameters must be measured and tuned — they are not guarantees.

04 · RELIABILITY

At-least-once + idempotency

At-least-once delivery means duplicates happen: workers claim jobs atomically and downstream side effects must be idempotent. Retries space out with backoff and jitter; after 5 attempts a message drains to a dead-letter queue with alarms.

Design patterns applied

Named patterns a reviewer can check against.

Queue-based load leveling

Producers never call workers directly — the queue absorbs peaks so workers size for average, not peak load.

Competing consumers

Each fleet polls one queue; each delivery goes to one worker. Duplicate delivery is still possible, so processing must tolerate repeated attempts.

Dead-letter queue

Messages that fail repeatedly drain to a DLQ with alarms — failed jobs become visible, not invisible.

Retry with backoff + jitter

Transient failures retry exponentially; jitter prevents synchronized retry storms.

Idempotent consumers

At-least-once delivery means duplicates; atomic job claims and idempotent downstream side effects make repeated attempts safe.

Circuit breaker

Flaky external dependencies fail fast instead of piling up blocked workers.
