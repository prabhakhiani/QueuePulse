Project purpose

What QueuePulse demonstrates.

QueuePulse is a queue monitoring dashboard — an educational prototype that demonstrates how engineering teams watch over background job systems. It visualizes the key signals of a healthy (or unhealthy) job pipeline: how many jobs are being processed, how many are waiting in each queue, how many fail, and how busy the worker fleet is.

The dashboard is built as a multi-page web application with simulated data. A shared demo state is stored in the browser, so the Overview, Metrics, Activity and Workers pages all describe the same fictional system. Every interactive control — refresh, filters, sorting, worker actions — works against that simulated state, making the project a safe sandbox for exploring dashboard concepts.

Key features

What each page of the dashboard does.

▦ Overview dashboard

Jobs processed, queue depth, failed jobs and active workers at a glance, with a throughput chart, job-status distribution donut and a recent-activity feed.

⌁ Performance analytics

Throughput over time, queue-depth trend, failure-rate statistics and per-worker utilization, with a 1H / 6H / 24H / 7D time-range selector.

≡ Activity logs

Searchable by job ID or event name, filterable by status, sortable by every column, with clear status badges, timestamps and an empty state.

◎ Workers & queues

Worker status cards with simulated pause, fail and recover actions, plus queue cards showing pending and processing job counts.

▤ Responsive design

A single dark-theme design system adapts from laptops to tablets to phones, with accessible contrast and readable tables.

⚙ Zero dependencies

Hand-drawn canvas charts, vanilla JavaScript and plain CSS — no frameworks, no build tools, no external libraries.
